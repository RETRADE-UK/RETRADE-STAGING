## Audit findings addressed

| Finding | Change and evidence |
| --- | --- |
| Busy searches could never complete their first baseline because both pages were always full | A complete distinct page overlapping persisted IDs ends the newest-window scan. Duplicate-filled pages do not prove overlap. A first saturated scan stays incomplete and silent; a subsequent overlapping cycle can complete the baseline. |
| Pending candidates were inserted once and could never become confirmed | Transactional pending-to-confirmed updates preserve first-seen time, store separate confirmation time and queue at most one alert. Initial-baseline candidates remain silent. |
| Skipped monitors held leases until expiry, wasting later cycles | Every tick releases remaining claims. Claimed batches run never/least-recently scanned monitors first, avoiding the unspecified order of UPDATE RETURNING. Global lease release runs even if claim release fails. |
| A crash on the final push attempt could leave a job permanently sending | Expired final attempts become failed with an explicitly unknown delivery outcome; cron wakes once for this recovery. |
| Comparison used the latest feed page as its entire detection history | Owner-checked SQL snapshot looks up exact evidence for every sampled Discord ID. Rejected candidates no longer crowd matches out of the displayed feed. Baseline exclusions count only excluded rows, not pagination sentinels. |
| Initial-load failure made Refresh unusable | Refresh works before data exists and retries bootstrap. |
| Source/monitor health never updated automatically | Visible-page polling uses a read-only status operation plus feed refresh, with stale-response fencing. Unchanged controls retain DOM/focus. |
| Closing the builder during a save could access a removed dialog or close a newer one | Save completion owns its original dialog and cannot remove another draft. Writes still wait for server confirmation. |
| Editing the Canon preset could reject user-added phrases as unknown Canon IDs | Existing Canon codes retain aliases; added phrases enter the custom-model list. |
| Switching monitors briefly displayed previous monitor evidence | Selection clears prior results and comparator export state before loading the new monitor. |
| Push tests always said queued, even after provider acceptance or subscription expiry | The reply reports queued, accepted, failed or expired state. Acceptance is still not phone receipt. |
| Feed lacked practical inspection tools | Safe supplied-photo gallery, manual Vinted search links preserving price/search settings, comparison CSV sample export and p95 timing display. Manual search does not enforce all local model rules. |
